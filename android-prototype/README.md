# Android APK-прототип

Это небольшой нативный Android-контейнер для кликабельного интерфейса из `../ui-prototype/`. Приложение открывает локальные HTML/CSS/JS-файлы из APK assets в `WebView`; демонстрационные экраны и карта работают без игрового сервера. Интернет нужен только для проверки сборок на GitHub и скачивания APK.

## Что входит в прототип

- Вертикальная Android-оболочка с фирменной заставкой, иллюстрацией парящего города и точным названием «Эхо Астры».
- Пять базовых иллюстраций боевых классов. Профессия остаётся отдельным UI-значком, выполненным в SVG; профессиональные предметы не добавляются в классовый арт.
- Выбор аватара только из пяти встроенных изображений; загрузка пользовательских фотографий не предусмотрена.
- Трёхмасштабная карта: локальный участок 10 × 10 клеток, биом 100 × 100 и общий мир 1 000 × 1 000. Стартовая позиция находится в городе Лиор; прежние водные клетки заменены белыми облаками, куда нельзя войти без транспорта.
- Часы показывают московское и игровое время рядом: за 1 час МСК проходит 5 игровых часов. Базовый шаг на соседнюю клетку — 6 секунд; класс и профессия немного меняют время (Следопыт быстрее Стража). Игровой ETA учитывает коэффициент 1:5; позиция и незавершённый шаг сохраняются локально. Квестовые сроки также считают игровое время.
- Пошаговый одиночный бой против Эхо: атака, классовый навык, защита, лечебные настои, отступление, победа/поражение и локальные награды. Текущий бой и счёт сохраняются на устройстве.
- Единый центр «Связь»: гильдейский чат, общение игрового сообщества (общий чат, поиск группы, обмен) и отдельный канал поддержки. Сообщения хранятся локально в демо и не доставляются другим игрокам или операторам без backend.
- Настройки класса/профессии и проверка обновлений через `apk-output/version.json`; если манифест недоступен, приложение резервно проверяет `releases/latest`.
- Встроенная загрузка APK без браузера: приложение проверяет SHA-256, идентификатор пакета, версию и подпись, затем передаёт APK системному установщику Android.
- Прототип работает без игрового сервера: нет аккаунтов, сетевой группы, общей экономики или синхронизированного прогресса.

## Проверка и установка обновлений

GitHub Actions собирает APK, присваивает сборке монотонный `versionCode`, сохраняет APK и `version.json` в Arena-ветку и публикует версионированный GitHub Release. Клиент сравнивает код версии установленного приложения с опубликованным кодом. После нажатий «Проверить» и «Скачать и установить в приложении» APK скачивается в закрытый кэш приложения (внешний браузер не открывается), SHA-256 проверяется по манифесту, затем проверяются package ID, версия и сертификат подписи. Проверенный APK передаётся `PackageInstaller` Android.

Системные ограничения обязательны: Android попросит включить для «Эхо Астры» разрешение «Установка неизвестных приложений» (обычно один раз) и подтвердить установку в системном окне. Тихая установка или обход системного подтверждения не выполняются.

### Постоянная подпись APK

Чтобы APK обновлялись поверх друг друга, сохраняйте один PKCS#12 keystore и задайте в GitHub repository Actions secrets:

- `ANDROID_SIGNING_KEYSTORE_BASE64` — содержимое keystore в Base64;
- `ANDROID_SIGNING_KEYSTORE_PASSWORD` — пароль keystore (и ключа).

Workflow использует фиксированный alias `echo-astra-release`; отпечаток созданного сертификата SHA-256: `3B:06:51:6E:30:9A:64:CE:02:5B:93:12:50:27:CC:B6:1D:B1:C0:17:CC:F6:3F:56:B0:C3:66:43:FF:AE:49:B7`. Keystore можно создать на доверенной машине командой `keytool -genkeypair -alias echo-astra-release -keyalg RSA -keysize 2048 -validity 10000 -storetype PKCS12 -keystore echo-astra-release.p12 -dname "CN=Echo Astra release"`; пароль вводится интерактивно. Кодируй файл в Base64 без переноса строк (`base64 -w0 echo-astra-release.p12`) и добавь оба значения в Settings → Secrets and variables → Actions в GitHub. Сохрани резервную копию keystore отдельно и надёжно: при потере ключа следующие APK снова нельзя будет обновить поверх.

Секреты не должны попадать в Git, артефакты или логи. Без обоих секретов Actions может выполнить тестовую сборку, но не опубликует её как новую версию. Локальная сборка без этих секретов использует стандартную debug-подпись и не годится для обновления стабильной сборки.

Текущий APK 0.2.15 был собран CI с временной debug-подписью; его приватный ключ не сохранён. Поэтому Android не может установить новый APK с постоянным ключом поверх 0.2.15. Для перехода на первую стабильную подпись потребуется один раз удалить старое приложение и установить миграционную сборку заново; удаление приложения сотрёт локальные данные. После этой миграции будущие сборки с тем же ключом можно скачивать и устанавливать из приложения.

## Сборка APK локально

Нужны JDK 17, Android SDK (Android 35 и Build Tools 35.0.0) и Gradle 8.9. Из корня проекта:

```bash
cd android-prototype
gradle --no-daemon :app:assembleDebug
```

Готовый устанавливаемый debug APK появится здесь:

```text
app/build/outputs/apk/debug/app-debug.apk
```

На подключённое Android-устройство его можно установить командой `adb install -r app/build/outputs/apk/debug/app-debug.apk`. Для ручной установки скачанного файла Android может попросить разрешить установку APK из выбранного приложения-файлового менеджера.

## Сборка через GitHub Actions

Workflow [Build Android UI prototype APK](../.github/workflows/android-prototype.yml) запускается после изменения `android-prototype/` или `ui-prototype/`, а также вручную через `workflow_dispatch`. Каждая успешная сборка запускает синтаксические проверки и тесты движков перемещения и боя, затем проверяет подпись APK, HTML/CSS/JS, логотип, пять классовых иллюстраций, семь SVG-значков профессий и включение игровых движков; после этого публикуется artifact **Echo-Astra-UI-Prototype-debug-APK**.

При push изменений в текущую Arena-ветку проверенный APK и манифест сборки автоматически публикуются в `apk-output/`; workflow также прикрепляет APK к GitHub Release для совместимости со старым приложением.
